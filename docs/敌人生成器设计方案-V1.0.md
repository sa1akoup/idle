# 敌人生成器设计方案 V1.0

> 目标：把当前写死的 4 种敌人扩展为一套可复用的敌人生成体系，支持按模板生成变体，覆盖
> 属性（血量/压力）、类型（杂鱼/精锐/BOSS）、出现位置、掉落物（背包类型）、
> 武器/弹药/护甲装备等完整单位定义，并对实际战斗与掉落流程零侵入接入。

> **当前实现状态（2026-08-31）**：模板表、确定性变体生成和快照物化已经落地。
> 数据库中的 `EnemyTemplateDef` 引用会在构建 `ScenarioSnapshot` 时转换为独立的
> `engine.Enemy`；战斗和掉落只消费快照中的运行时敌人。本文中的“现状”按这条链路描述，
> 后续规划单独标注。

---

## 1. 现状盘点

### 1.1 现有数据模型（模板 + 运行时敌人）

```go
// backend/internal/models/models.go
type EnemyTemplateDef struct {
    ID, Name, Kind string
    SpawnTags     []string
    Tier          int
    HPBase, HPFlux, HPFloor, HPCap int
    StressBase, StressFlux, StressFloor, StressCap int
    WeaponPool, ArmorPool, BackpackPool []WeightedRef
    AmmoLevelMin, AmmoLevelMax, AmmoRoundsBase int
    AmmoRoundsMult float64
    BossLootItems []WeightedRef
    BossAmmoDrop bool
    BossWeaponID, BossArmorID, BossName string
}

// backend/internal/engine/types.go
type Enemy struct {
    ID, Name, Kind, VariedFrom string
    HP, StressThreshold int
    Perception, Stealth, Agility int
    WeaponID, ArmorID, AmmoID string
    AmmoRounds, Evasion, Mobility, Suppress int
    BackpackContainerID string
}
```

`EnemyTemplateDef` 是数据库目录模型，`engine.Enemy` 是固化进场景快照的运行时 DTO；
运行时不再依赖独立的 `models.EnemyDef`。

### 1.2 现有种子模板（seed_enemy_templates.go）

| 模板 ID | 名称 | Kind | HP 基础值 | 武器池 | 护甲池 | 弹药等级 | 背包池 |
|---|---|---|---|---|---|---|---|
| template_patrol | 巡逻小队 | grunt | 80 | pistol / SMG | light_01 | 1-3 | basic |
| template_guard | 据点守卫 | guard | 100 | SMG / shotgun / pistol | light_01 / armor_6b2 | 2-4 | guard |
| template_elite | 精锐小队 | elite | 120 | rifle | heavy_01 | 4 | elite |
| template_sniper | 狙击哨位 | sniper | 70 | sniper rifle | light_02 | 3-5 | basic |

种子还包含 scav、rogue、raider、cultist 和多个 boss 模板，完整定义位于
`backend/internal/config/seed_enemy_templates.go`。

### 1.3 出现位置（双通道）

1. **节点固定**：`NodeDef.EnemyID`（seed_map.go，节点引用模板 ID）
2. **事件遭遇池**：`EncounterPoolEntry{MapID, Role, EnemyID, Weight}`（seed_events.go），
   条目同样引用模板 ID，运行时由引擎 `resolveEnemyID(role, rng)` 按权重抽取已物化变体

构建快照时，节点引用和遭遇池条目分别生成独立变体，并把内存中的 `EnemyID` 替换为
变体 ID；数据库种子仍保留模板引用。

### 1.4 掉落链路

- 击杀后 `run_simulation_detail.go:244` 调 `state.CollectContainer(enemy.BackpackContainerID, ...)`
- 背包容器定义在 seed_containers.go（enemy_backpack_basic/guard/elite），按物品类别加权出 loot

### 1.5 校验防线

- `snapshot.go` 的 `Validate` 检查快照敌人引用的武器/护甲/弹药/背包容器必须存在，
  弹药口径与武器匹配、弹药等级 1-6。`buildScenarioSnapshot` 在返回前执行该防线。

## 2. 设计目标与范围

| 维度 | 目标 |
|---|---|
| 可复用 | 模板化定义敌人"类"，一次定义、到处生成 |
| 类型 | grunt（杂鱼）/ guard（守卫）/ elite（精锐）/ boss / sniper（可扩展） |
| 属性 | HP、压力阈值、感知/潜行/敏捷/闪避/机动/压制等，支持区间浮动 |
| 装备 | 武器、护甲、弹药（口径+等级）按池加权选择 |
| 掉落 | 背包容器池按权重选择、boss 专属掉落 |
| 位置 | 节点固定 & 遭遇池加权 & 难度缩放 |
| 接入 | 对战斗/掉落/快照零侵入（生成器在快照物化前运行） |

**非目标**：本方案不做完整 AI 行为树、不做多波次刷怪，仅覆盖"单位生成"本身。

---

## 3. 核心设计决策（Tradeoff）

| 决策点 | 选择 | 理由 |
|---|---|---|
| 变体来源 | **模板 + 参数变体**，不搞纯随机 | 可复用≠随机；纯随机难调试、难平衡 |
| 生成层 | service/engine 之间的装配层，进快照前生成 | 战斗只认 `snapshot.Enemies`，对战斗零侵入 |
| 生成时机 | Session 启动时物化一次 → 快照固化 | 与现有持久化一致，日志回放稳定 |
| 随机性 | 生成器吃注入 `rng *rand.Rand` | 保证 replay / 日志可复现 |

## 4. 数据模型

### 4.1 敌人模板表 `EnemyTemplateDef`（已实现）

描述“一个敌人怎么长出来”，由 `models.EnemyTemplateDef` 持久化：

```go
// 权重引用：{Ref: "rifle_ak", Weight: 100}
type WeightedRef struct {
    Ref    string `json:"ref"`
    Weight int    `json:"weight"`
}

type EnemyTemplateDef struct {
    ID           string   `gorm:"primaryKey" json:"id"`   // template_scav_grunt 等
    Name         string   `json:"name"`                     // 显示名（可留空走变体名）
    Kind         string   `json:"kind"`                     // grunt / guard / elite / boss / sniper
    SpawnTags    []string `gorm:"serializer:json" json:"spawnTags"` // outdoor/indoor/underground/far 等位置过滤
    Tier         int      `json:"tier"`                     // 0 杂鱼 ~ 3 boss 基础数值档

    // 属性：基础值 + 浮动区间；每项可配 ±Flux，结果再 clamp 到 Floor ~ Cap
    HPBase, HPFlux, HPFloor, HPCap int
    StressBase, StressFlux, StressFloor, StressCap int
    PerceptionBase, PerceptionFlux int
    StealthBase, StealthFlux int
    AgilityBase, AgilityFlux int
    EvasionBase, EvasionFlux int
    MobilityBase, MobilityFlux int
    SuppressBase, SuppressFlux int

    // 装备池（可多个，按权重抽取）
    WeaponPool []WeightedRef `gorm:"serializer:json" json:"weaponPool"`
    ArmorPool  []WeightedRef `gorm:"serializer:json" json:"armorPool"`
    AmmoLevelMin, AmmoLevelMax int     // 弹药等级区间（口径随武器自动匹配）
    AmmoRoundsBase int `json:"ammoRoundsBase"`
    AmmoRoundsMult float64 `json:"ammoRoundsMult"` // 弹量系数

    // 掉落
    BackpackPool  []WeightedRef `gorm:"serializer:json" json:"backpackPool"`   // 多个背包池，按权重选
    BossLootItems []WeightedRef `gorm:"serializer:json" json:"bossLootItems"` // boss 专属物品掉落（可选）
    BossAmmoDrop  bool `json:"bossAmmoDrop"`   // boss 是否额外掉弹药
}
```

### 4.2 运行时变体使用 `engine.Enemy`（已实现）

生成器返回纯引擎 DTO，不把 GORM 模型带入战斗层：

```go
type Enemy struct {
    // ...运行时战斗字段...
    Kind      string `json:"kind"`        // grunt/guard/elite/boss/sniper
    VariedFrom string `json:"variedFrom"` // 来源模板 ID，调试用
}
```

`Kind` 和 `VariedFrom` 已直接存在于 `engine.Enemy`，不需要额外的敌人持久化表。

### 4.3 位置挂载（复用现有机制 + 轻量扩展）

1. **节点固定**：`NodeDef.EnemyID` 保持，数据库值指向模板，快照构建时替换为变体 ID。
2. **事件遭遇池**：`EncounterPoolEntry.EnemyID` 保持同一口径，当前不增加并行的
   `TemplateID` 字段，避免两套引用语义。

## 5. 生成器核心

位置：`backend/internal/service/enemygen.go`。生成器由快照装配层调用，返回纯 engine DTO。

```go
// GenerateEnemy 根据模板 + 生成上下文产出单个合法 engine.Enemy
func GenerateEnemy(rng *rand.Rand, template models.EnemyTemplateDef, ctx GenerateContext, catalog EnemyGenerator) (engine.Enemy, error)
```

```go
type GenerateContext struct {
    // 难度缩放输入
    PlayerLevel     int     // 玩家成长
    Heat            int     // 当前热度
    NodeValueTier   int     // 节点价值档（高价值节点偏强）
    Boss            bool    // 是否强制 BOSS 规则
}
```

### 5.1 生成流程（确定性 + 可注入随机）

1. **取模板**：按节点或遭遇池条目的 `EnemyID` 查找模板。
2. **缩放**：`scale = 1 + (PlayerLevel-基准)*α + Heat*β + NodeValueTier*γ`
   - HP / StressThreshold / 战斗相关属性 × scale
   - 结果 clamp 到 `Floor ~ Cap`
3. **掷变体**：属性在 `Base ± Flux` 内浮动（`rng` 驱动）
4. **选装备**：按 WeaponPool / ArmorPool 权重抽；
   弹药按武器口径在 `[AmmoLevelMin, AmmoLevelMax]` 内取合法弹药
   （**复用现有快照校验规则**：口径匹配、等级 ≤ 6、商人可售级别 ≤4）
5. **选掉落**：按 BackpackPool 权重抽一个容器池 → 写入 `BackpackContainerID`
6. **Boss 特殊**：当前生成器支持固定武器、护甲和命名；`BossLootItems`、`BossAmmoDrop`
   已进入模板模型，直接掉落接入仍属于后续扩展。
7. **校验**：生成器先校验目录引用；最终输出再由 `snapshot.Validate` 做完整性检查。

### 5.2 批量生成入口

```go
// materializeEnemies 在构建 ScenarioSnapshot 时，把节点/遭遇池模板引用物化为快照敌人。
// 当前实现按节点和遭遇池条目各生成一个独立变体，并返回两组引用映射。
func materializeEnemies(templates []models.EnemyTemplateDef, nodes []models.NodeDef,
    pools []models.EncounterPoolEntry, weapons []models.WeaponDef, armors []models.ArmorDef,
    ammos []models.AmmoDef, containers []models.LootContainerDef) ([]engine.Enemy, map[string]string, map[string]string, error)
```

## 6. 类型（Kind）规划

| Kind | 定位 | 典型模板特征 | 掉落倾向 |
|---|---|---|---|
| grunt | 杂鱼小兵 | HP 低、单发武器、便宜背包 | low_value 容器 |
| guard | 守卫 | 中量 HP、冲锋枪/霰弹、中型背包 | combat/medium 容器 |
| elite | 精锐 | 高 HP、步枪、重甲、好背包 | high_value 容器 |
| boss | BOSS | 极高 HP、专属武器、专属掉落 | 专属容器 + BossLootItems |
| sniper | 狙击 | 低 HP、高感知、栓动远程 | 侦察/工具掉落 |

每种 Kind 建议至少 1-2 个模板，后续扩展只需加种子行。

---

## 7. 出现位置策略

| 来源 | 用法 |
|---|---|
| 节点固定 | 高危节点（海关办公楼/集装箱场）配 elite/boss 模板，普通节点配 grunt/guard |
| 事件遭遇 | `EncounterPoolEntry.EnemyID` + Weight 加权，同一 Role 下挂多个模板，越强权重越低 |
| 难度缩放 | 节点 ValueTier 高 → 生成器上浮 Tier；玩家热度高 → 敌群更凶 |

---

## 8. 掉落机制

- 击杀后沿用 `CollectContainer(BackpackContainerID, ...)`；
- 当前运行时敌人保留单个 `BackpackContainerID`，多个背包或副袋需要后续扩展，
  暂不新增 `BackpackContainerIDs` 字段；
- `BossLootItems` 和 `BossAmmoDrop` 已进入模板模型，直接掉落接入仍属于后续扩展；
- 掉落物类别权重继续复用 `seed_containers.go` 现有容器池。

## 10. 风险与注意

- **快照校验是硬防线**：生成器输出必须过 `snapshot.Validate`，非法引用直接炸 → 用测试锁死
- **Seed 幂等坑**：新模板表沿用 `Select("*")` 全量更新，防旧行字段空
- **确定性**：生成必须吃注入 RNG，保证 replay / 日志可复现
- **兼容**：节点和 `EncounterPoolEntry.EnemyID` 字段保留，数据库历史 migration 不回写；当前字段值按模板引用解释
- **弹药合法性**：生成弹药必须走现有校验（口径匹配、等级 ≤6、商人可售 ≤4），避免生成出无法补给的弹药
