# V0.3 详细改造方案

> 对应产品方向：`搜打撤放置游戏V0.3更新方向.md`  
> 日期：2026-09-03  
> 引擎：新会话 `exploration-engine-v18`；存量 `v17` 继续模拟但不应用新成长；`v16` 只收尾

## 1. 范围

本方案覆盖 V0.3 的 A/B 两阶段。C（联络人档案）本版不做。第二张图、黑市、Boss 见 V0.4（不做 Scav）。

| 阶段 | 交付 | 不交付 |
|---|---|---|
| A | 声望、机械商人 LL1、技能/主属性成长、白板 25、情报进快照、规划中设施 | 合同 UI、新地图 |
| B | 商人合同定义、接取、手动上交、结算核对、探索页当前目标 | 比特币生产、撤离后自动上交 |
| C | 本版不做 | 联络人档案、跨局情报标记、Wipe、跳蚤市场、第二张图 / 黑市 / Boss（见 V0.4） |

## 2. A 阶段设计

### 2.1 引擎版本

| 版本 | 行为 |
|---|---|
| v16 | 不模拟，直接按 `engine_migrated` 收尾 |
| v17 | 现有 `SimulateRun`：撤离成功武器熟练度 +1，无技能/情报 |
| v18 | 技能成长 + 主属性门槛 + 情报侦察/事件触发 |

入口：`SimulateRunVersion`。测试与新会话走 v18；worker 按 Session 上的 `engine_version` 分派。

`SchemaVersion` 保持 `exploration-snapshot-v9`。`Tuning.Encounter` 新增字段缺省 0，旧快照 JSON 仍能通过校验。

### 2.2 技能成长（仅 v18，且本局结果为 success）

单局每项最多 +1，封顶 100。

| 来源 | 技能 |
|---|---|
| 属性判定事件成功 | 对应 `EventCheck.Attribute` |
| 潜行绕行成功（未交战） | 潜行 |
| 使用医疗品自动治疗 | 医疗 |
| 成功撤离 | 生存 |
| 有效交火（耗弹或近战）后撤离成功 | 原武器熟练度 +1 |

主属性：对应子技能从低于门槛跨到 ≥20/40/60/80 时 +1，封顶 100。

| 子技能 | 主属性 |
|---|---|
| 潜行、感知 | 敏捷 |
| 交涉、幸运 | 魅力 |
| 生存、抗压 | 力量 |
| 工程、医疗 | 智力 |

空气过滤 `PhysicalSkillGrowthPercent`：对潜行/生存/抗压，若加成 > 0 则本局额外再尝试 +1（仍封顶 100）。情报中心不改技能，只改侦察与事件。

结算：`updateCharacterFromEngine` 必须写回主属性和八项技能，不能只写生命/压力/熟练度。

### 2.3 情报加成

`buildScenarioSnapshotTx` 读取藏身处 `IntelBonusPercent`，写入：

- `Tuning.Encounter.IntelReconBonus` = 情报百分比（10 → 侦察 +10）
- `Tuning.Encounter.IntelEventBPBonus` = 情报百分比 × 20（10 → 探索事件 TriggerBP +200）

`calcRecon` 加上 `IntelReconBonus`。事件抽选时，`category == "exploration"` 的绑定使用提高后的 TriggerBP。v17 快照字段为 0，行为不变。

### 2.4 商人声望

`AwardReputationForUser` 改为可在已有事务内调用的 `awardReputationTx`。

| 触发 | 奖励 |
|---|---|
| 会话成功结束（非失能） | 武器商人 +1 |
| 向某商人出售 | 成交额 ≥ 200 则 +1，≥ 1000 再 +1，单次最多 2 |

进行中的每一局不给好感，避免一局长挂机刷满 N4。合同将是后续主要来源。

机械商人 `Open: true`。存量用户用数据适配 v5 将 `mechanical` 的 `Unlocked` 置真。

目录：机械类物品按价格补好感门槛（≤100 为 0，≤250 为 10，≤500 为 20，其余 30）。LL1 只能买基础工具，藏身处关键件仍靠搜刮或更高好感。

### 2.5 角色白板

新用户：四项主属性 25，子技能和熟练度仍 0。生命按力量计算，上限 95，开局拉满。

存量：数据适配 v5 仅处理「四项主属性均为 0」的角色，不重跑 v4 的目录清扫。生命若处于旧上限 90，抬到新上限 95。

图书馆升级条件 `hideout_management` 改为 `engineering`，避免未知技能名误用默认值 50。

### 2.6 藏身处规划中

后端 `HideoutFacilityView.Runtime`：`active` 或 `planned`。

规划中：`booze_generator`、`bitcoin_farm`、`scav_case`、`shooting_range`、`gym`、`library`、`hall_of_fame`。

这些设施仍可升级（材料槽），前端标明「规划中，本版本不生产/训练」，删除「可生产比特币」等假文案。

## 3. B 阶段设计（合同）

### 3.1 数据

新增表（双方言 migration）：

- `quest_defs`：静态合同。字段含 `id, merchant_id, chain_index, name, desc, objective_type, objective_json, reward_json, next_quest_id`
- `user_quests`：`user_id, quest_id, status(available/active/completed), progress_json, accepted_at, completed_at`

目标类型：`extract_item`、`visit_node`、`style_extract`、`defeat_role`、`survive_runs`。

奖励：现金、指定商人好感、解锁下一条。

### 3.2 运行时

接取后写入 `ScenarioSnapshot.Contracts`（只读目标）。引擎在 `RunResult` 中报告访问节点、击倒角色、风格、带出物品；service 在 `settleEngineRun` 同一事务内累加进度。

物品上交只走 `POST /api/quests/:id/turnin`，必须玩家在探索页手动点上交。撤离成功、仓库已有目标物时也不自动交付：FIR 材料同时用于合同、藏身处升级和制造，自动上交会抢走玩家的用途选择。局内不弹窗。

快照必须包含合同，避免配置更新改变进行中的 Session。引擎版本若只增加只读合同字段且 v18 已忽略未知 JSON，可不升 v19；若引擎要按合同改路线，再升版本。B 阶段默认 **不改路线**，只核对结果。

### 3.3 API / UI

- `GET /api/quests` 当前可接/进行中/已完成
- `POST /api/quests/:id/accept`
- `POST /api/quests/:id/turnin`

探索页是合同入口：当前目标、差什么、交给谁、奖励、接取与上交。不单独做商人任务页。

种子：开放商人各一条线性链，材料与藏身处升级重叠。

## 4. C 阶段（本版不做）

联络人档案、`user_intel_flags`、跨局情报解锁钥匙门，全部推迟。本版钥匙作为同图搜刮物进快照，开门不依赖档案。

## 6. 风险

| 风险 | 处理 |
|---|---|
| 进行中 v17 Session 被新成长污染 | `SimulateRunVersion` 按版本分派，pending run 仍用已存结果 |
| 长会话刷好感 | 好感按会话结束给，不按局 |
| 机械商人买空藏身处材料 | 价格门槛把关键件放到 rep 10～30 |
| v4 数据适配破坏性清扫 | v5 独立版本记录，不重跑 v4 |
| 未知技能名默认 50 | 图书馆条件改为 `engineering` |

## 7. 验证

A 阶段：

- 引擎：相同 seed 回放仍一致；v17 不涨技能；v18 撤离成功涨生存/熟练度；绕行成功涨潜行。
- 服务：会话成功结束武器商人 +1；出售达额给对应商人好感；机械商人可浏览且低好感买不到高价件。
- 存量：全 0 角色升到 25，生命上限 95。
- 前端：藏身处规划中设施文案；角色页属性不再全 0。

B 阶段：接取后快照带合同；visit/击倒/风格/生存在成功撤离后累加；extract_item 只在手动上交时扣 FIR，商店货不能交，撤离成功不自动扣。

C 不在本版验证。
